# handoff-260305-1.md

## Context

`produm` (project-dumper) currently generates a project dump as a large text file intended for LLM ingestion and human inspection. The tool walks a directory, builds a directory tree, lists files, and includes file contents.

A new package, `simdoc` (simple-document), is now available on PyPI and will become the canonical document generation backend.

This handoff defines the refactor required to:

1. Replace the current string-based renderer with a `simdoc` based renderer.
2. Add PDF export capability via Pandoc.
3. Introduce a `clean` command to remove previous dump artifacts.
4. Slightly restructure the CLI while preserving the current user workflow.

This document is the **authoritative execution contract** for implementing these changes.

---

# Non‑Goals / Do Not Touch

The following parts of the system must **not be modified unless absolutely required**:

- File discovery logic
- Ignore / filtering behavior
- Directory traversal logic
- Max file size rules
- Tree generation logic

Only the **document rendering layer and CLI orchestration** should be modified.

---

# Locked Design Decisions

## D1 — CLI Structure

The CLI will support explicit subcommands.

```
produm dump <path>
produm clean <path>
produm <path>
```

Behavior:

| Command | Behavior |
|-------|------|
| `produm dump` | Dump only |
| `produm clean` | Clean only |
| `produm` | Clean then dump |

Example:

```
produm .
```

Equivalent to:

```
produm clean .
produm dump .
```

---

## D2 — Default Output Format

Markdown is the default output format.

Output filename:

```
<project>-dump-YYYYMMDD-HHMM.md
```

Example:

```
project-dumper-dump-20260305-1044.md
```

---

## D3 — PDF Export

PDF export is triggered via:

```
produm dump <path> --pdf
```

Behavior:

- Produces **PDF only**
- Does not retain the Markdown file

Example:

```
project-dumper-dump-20260305-1044.pdf
```

PDF generation uses:

```
simdoc.Doc.save_pdf()
```

Runtime requirements:

- `pandoc`
- `xelatex`

---

## D4 — Document Renderer

The existing string-based renderer will be **fully replaced** with a `simdoc` renderer.

Document construction must use:

```
Doc()
heading()
paragraph()
codeblock()
```

Example pattern:

```python
from simdoc import Doc

 doc = Doc(title="Project Dump — project")
 doc.heading("Directory Tree")
 doc.codeblock(tree_text)
```

File contents should be inserted as fenced code blocks.

---

## D5 — Cleaning Strategy

`produm clean` removes only files matching the strict regex:

```
^[a-zA-Z0-9._-]+-dump-\d{8}-\d{4}\.(md|pdf)$
```

Only files matching this exact format may be removed.

---

## D6 — Cleaning UX

Cleaning is **non-interactive**.

```
produm clean .
```

Behavior:

- Deletes matching files immediately
- Prints list of removed files

Preview mode:

```
produm clean . --dry-run
```

Shows files that would be deleted.

---

## D7 — Dependency Strategy

`simdoc` is a **hard dependency**.

`pyproject.toml`

```
dependencies = [
    "simdoc"
]
```

---

## D8 — Document Title

The document title must be:

```
Project Dump — <project_name>
```

Example:

```
Project Dump — wav-to-freq
```

---

## D9 — Table of Contents

A Table of Contents must be included by default.

Location:

Immediately after the document title.

---

## D10 — Section Structure

The existing logical structure must remain unchanged.

Final document layout:

```
# Project Dump — <project>

## Table of Contents

## Directory Tree

## File List

## File Contents
```

---

## D11 — Timestamp Format

Timestamp format remains:

```
YYYYMMDD-HHMM
```

Example:

```
20260305-1044
```

# Specs

## S-260305-1 — Simdoc Renderer

The dump document must be built using `simdoc.Doc`.

Sections must be inserted in the following order:

1. Title
2. Table of Contents
3. Directory Tree
4. File List
5. File Contents

File contents must be represented as fenced code blocks.

---

## S-260305-2 — PDF Export

CLI flag:

```
--pdf
```

Behavior:

- Build document with simdoc
- Call `save_pdf()` instead of `save()`

---

## S-260305-3 — Cleaning Command

The command:

```
produm clean <path>
```

Must delete files matching the dump regex in the specified directory.

---

## S-260305-4 — Default Workflow

Running:

```
produm <path>
```

Must perform:

1. `clean`
2. `dump`

in that order.
